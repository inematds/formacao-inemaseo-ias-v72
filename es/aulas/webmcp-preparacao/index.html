Clase 7 · 19 min

De lo encontrado a lo usado: WebMCP como preparación

El SEO hace que el sitio sea encontrado; el siguiente paso es que un agente en el navegador lo use. WebMCP propone que la página ofrezca herramientas con nombre, descripción y parámetros. Es un borrador de comunidad del W3C, sin navegador estable: vale la pena preparar una página de prueba, no reconstruir el sitio ni prometer ranking.

Comenzar la clase

En esta clase vas a

  1. 1Qué es WebMCP y en qué estado está (especificación del 16/10/2026)
  2. 2Los campos de una herramienta: nombre, descripción, schema, execute
  3. 3Feature detection, cancelación y camino manual
  4. 4Dónde tu sitio ganaría una herramienta, y dónde no

Objetivo: registrar una herramienta de solo lectura con document.modelContext.registerTool() en una página de prueba, como preparación.

02 · Preparar sin exagerar

Haz clic en cada paso.

1. Elegir un recorrido

Empieza por algo que solo consulta: horario, disponibilidad, precio de lista, estado de un pedido público. Nada que compre, envíe o borre.

Si el sitio no tiene un recorrido útil para un agente, la decisión correcta es no tener herramienta.

2. Describir bien

Nombre con verbo y específico (consultar_horarios). Descripción que diga qué hace, qué devuelve y el límite ("solo lectura; no agenda"). Cada parámetro con tipo y descripción en el inputSchema.

3. Detectar y volver al modo manual

Registra solo si el navegador expone la API ('modelContext' in document). Si no la expone, la página sigue igual para la persona, con el camino manual visible.

Guarda el AbortController: abortar quita la herramienta.

4. Nombre nuevo, cursos antiguos

La especificación cambió: la API ahora está en document.modelContext. Los cursos WebMCP antiguos de INEMA y muchas guías usan el nombre anterior, en el objeto navigator, y una forma declarativa en formularios que no aparece en el texto de la especificación del 16/10/2026 (por confirmar en el explainer).

Para profundizar (seguridad, schemas, agentes), sigue la Formación WebMCP, teniendo en cuenta este ajuste de nombre.

03 · Una herramienta de solo lectura, para copiar

Página de prueba servida en HTTPS. Cambia los horarios por los tuyos.

horarios.html · página de prueba
<section id="horarios">
  <h1>Horario de atención</h1>
  <p>Lunes a viernes, 8h a 18h. Sábado, 8h a 12h. Domingo, cerrado.</p>
</section>
<p id="aviso-agente" hidden>Este navegador no ofrece herramientas a agentes. La información de arriba vale igual.</p>
<script>
  const horarios = { semana: "08:00-18:00", sabado: "08:00-12:00", domingo: "fechado" };
  const controle = new AbortController(); // controle.abort() tira a ferramenta
  if ("modelContext" in document) {
    document.modelContext.registerTool({
      name: "consultar_horarios",
      title: "Consultar horário de atendimento",
      description: "Devolve o horário de atendimento da loja para o dia pedido. Só leitura: não agenda nada.",
      inputSchema: {
        type: "object",
        properties: {
          dia: { type: "string", enum: ["semana", "sabado", "domingo"], description: "Dia a consultar" }
        },
        required: ["dia"]
      },
      annotations: { readOnlyHint: true },
      async execute({ dia }) {
        return { dia, horario: horarios[dia] };
      }
    }, { signal: controle.signal }).catch((erro) => console.warn("WebMCP:", erro));
  } else {
    document.getElementById("aviso-agente").hidden = false;
  }
</script>
Encabezado para páginas SIN WebMCP
Permissions-Policy: tools=()
Comprobar
grep -c "registerTool(" horarios.html
# 1
# publicada: o agente-ready detecta a ferramenta no código estático
python3 agente-ready.py https://seusite.com/teste/horarios.html --saida saida/teste
Ejemplo del repositorio

agente-ready encontró en inema.club 1 llamada registerTool() en document.modelContext y la política Permissions-Policy: tools=(self); el bloque WebMCP cerró en 100. En los sitios news y eventos, sin herramienta, el bloque quedó en 29.

Esto mide preparación. Ninguna IA promete citar ni posicionar mejor por esto.

  • registerTool(tool, options) rechaza nombre repetido, nombre o descripción vacíos y schema inválido.
  • options.signal: abortar quita la herramienta.
  • annotations: readOnlyHint, untrustedContentHint, consequentialHint.
  • Permissions-Policy: tools=() desactiva la API en la página y en los frames.

04 · Práctica: la página de prueba

No toques el sitio principal: usa una página de prueba.

E1 · Herramienta de solo lectura

40 min

Adapta el modelo a una consulta real de tu negocio, publícalo en una página de prueba en HTTPS y ábrelo en el navegador común.

Listo cuando: la página abre sin error en la consola, muestra el aviso del camino manual cuando el navegador no ofrece la API, y el grep por registerTool( devuelve 1.

E2 · Dónde sí, dónde no

20 min

Enumera 3 recorridos de tu sitio y decide para cada uno: herramienta de solo lectura, acción con confirmación humana o ninguna herramienta. Escribe el motivo.

Listo cuando: un texto corto con 3 recorridos, la decisión y el motivo de cada uno, y qué páginas reciben Permissions-Policy: tools=().
